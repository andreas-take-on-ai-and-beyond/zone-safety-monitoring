Reading guide — The diagram follows the 5-layer enterprise blueprint top-to-bottom. L1 Ingestion: Two Python producers emit a 5-signal JSON tick every 5 s to Kafka env_sensor_data (KRaft, port 9092). L2 Token Shield: Flink SQL 60 s tumbling window AVGs 12 readings before evaluating zone-specific HAVING thresholds — single spikes (e.g. CHIP_BLOWOFF) are absorbed; scenario labels never leave this layer. Qualified events write to sensor_alerts. L3 Dispatch Bridge: agent_bridge.py consumes sensor_alerts (group: wxo-trigger-group), enforces 180 s ISA-18.2 cooldown, builds a structured prompt (RECURRENCE_STATUS + 5-signal snapshot + prior_dispatches count) via wxo_client.py, then issues two calls to wxO: POST chat/completions → GET /runs/{run_id}. Results are appended to dashboard_log.json; raw telemetry to sensor_log.json; permanent ledger to alert_history.json. L4 Agentic AI: The zone_safety_native native agent (react_intrinsic, gpt-oss-120b at temp 0) executes a fixed 6-step ReAct protocol using 5 deterministic Python tools. Tools ②③ read alert_history.json for cross-session recurrence reasoning. Tool ⑥ emits DISPATCH_PAYLOAD::{json} extracted by the bridge. L5 Oversight: Express (:4173) serves two rolling JSONL files with Cache-Control: no-store. The Carbon React SPA (g90 dark, React 18, Vite 5) polls every 3 s — no WebSocket push. Three tabs: AI Dispatches (accordion, KPI tiles, dept breakdown), Sensor Telemetry (5 SVG charts, threshold lines), Floor Plan (SVG 2-zone map, click-to-detail).
